1. COMMAND                                                          *:Diffundo*

:Diffundo earlier [count]                                  *:Diffundo-earlier*
    Open (or update) a vertical diff split showing the buffer as it was
    after |:earlier| [count]. [count] is anything |:earlier| accepts:
    `3`, `10s`, `2f` ... Default `1`. Relative to the state the split
    already shows, so repeating it walks further back.

:Diffundo later [count]                                      *:Diffundo-later*
    The same for |:later|.

:Diffundo search {pattern}                                  *:Diffundo-search*
    Find the undo state whose edit added a line matching {pattern}, show
    it in the diff split, and move the cursor to the match in your buffer
    (or to where the line was, if it is gone). {pattern} is a Vim regex:
    'ignorecase', 'smartcase' and 'magic' apply as for |/|. The search
    register |quote/| is not changed. Repeat to find the next older state.

:Diffundo search! {pattern}
    The same for a line that was removed.

    Search compares each undo state with the state it was edited from
    (its parent in the undo tree, see |undo-branches|), so switching
    branches never counts as an addition or removal.

:Diffundo focus                                              *:Diffundo-focus*
    Open the diff split and focus the history pane: the pane expands into
    the whole undo tree and takes the focus (see |diffundo-pane-keys|).

:Diffundo close                                              *:Diffundo-close*
    Close the diff split and its pane.

    Every subcommand opens a floating history pane next to the diff window
    showing the buffer's state and the diff's state, unless the pane is
    disabled with the `history` option (see |diffundo-options|).

==============================================================================
2. SETUP                                                        *diffundo-setup*

`require("diffundo").setup(opts)` is the only way to configure the plugin.
It merges |opts| over the built-in defaults below, so every setting is
optional and the plugin works unchanged with no `setup()` call at all. >lua

    require("diffundo").setup({
      history = false,                      -- no history pane
      glyphs = { write = "ⓦ" },             -- merged over the defaults
      date_format = "%Y-%m-%d %H:%M:%S",    -- or function(time) -> string
      history_width = 40,                   -- pane width
      fold_min = 3,                         -- expanded-view fold threshold
      keys = {
        pane = {                            -- pane-local keymaps (below)
          ["<cr>"] = false,                 --   unmap a default binding
        },
      },
    })
<

==============================================================================
3. OPTIONS                                                    *diffundo-options*

history (boolean, default true)
    When false, the commands open the diff split without the history pane.

glyphs (table, merged over `{ buffer = "@", write = "w", gap = "┆",
ellipsis = "…" }`)
    Glyphs the pane draws: `buffer` marks your buffer's state, `write` a
    state written to disk, `gap` the gap-row and fold-caption prefix,
    `ellipsis` the truncation marker.

date_format (string, or function(time: integer): string; default
"%Y-%m-%d %H:%M:%S")
    Formats the state timestamps in the pane's border title. A function is
    called with the state's time and must return the title text.

history_width (integer, default 40)
    The pane's width in columns, clamped to the diff window.

fold_min (integer, default 3)
    The expanded pane folds off-trunk branch stretches longer than this
    into `┆  N undos` captions.

The old `vim.g.diffundo_history`, `vim.g.diffundo_glyphs`,
`vim.g.diffundo_date_format`, `vim.g.diffundo_history_width` and
`vim.g.diffundo_fold_min` variables are removed; set the same options
through |diffundo-setup| instead.

4. PANE KEYS                                             *diffundo-pane-keys*

The pane's default keymaps are pane-local; no global keys are mapped and
`j`/`k` stay plain motions. Each default value is a Lua function of one
argument, the facade `api`:

    J       function(api) api.move_save(1) end    next written state
    K       function(api) api.move_save(-1) end   previous written state
    <cr>    function(api) api.place() end         diff the state under the cursor
    <c-cr>  function(api) api.apply() end         move the buffer to the state under the cursor
    q       function(api) api.collapse(true) end  collapse and return to the source
    <esc>   function(api) api.collapse(true) end  collapse and return to the source

Configure them through the `keys.pane` option: the table merges per key
over these defaults, so passing `<cr>` alone replaces only that binding and
leaves the other five intact. A value of `false` (or an empty string)
removes the default binding for that key. >lua

    require("diffundo").setup({
      keys = {
        pane = {
          ["<cr>"] = false,                              -- no longer mapped
          H = function(api) api.move_save(-1) end,       -- add a binding
          x = function(api) api.earlier() end,           -- commands work too
        },
      },
    })
<

The facade `api` is one table combining the command actions |:Diffundo|
exposes (`earlier`, `later`, `undo`, `search`, `focus`, `close`) with the
pane actions (`move_save`, `place`, `apply`, `collapse`), so a replacement
function receives everything it needs from its single argument.

==============================================================================
5. LUA API                                                        *diffundo-api*

All functions leave the current window and cursor unchanged and raise
errors instead of printing them. >lua

    local diffundo = require("diffundo")
    diffundo.setup(opts)                 -- see |diffundo-setup|
    diffundo.earlier(count)              -- count: string|nil, as :earlier
    diffundo.later(count)
    diffundo.search(pattern, opts)       -- opts.removed = true for search!
<
`search` returns nil when nothing matches, otherwise a table: >
    { seq, time, save, line, col, lnum }
<
`seq` is the state shown in the split, `line` the matched text, `col` the
0-based match column and `lnum` the line's number in the state that had it.

`require("diffundo.walker").steps(from_seq)` returns an iterator over undo
states with seq below `from_seq`, newest first, each `{ seq, parent,
time, save, lines, parent_lines, added, removed }`. It runs |:undo| in the
current buffer, so call it with the source buffer current and restore
afterwards.

`require("diffundo.history").rows(opts)` produces the sidebar's list the
same way: newest first, each `{ seq, time, save, added, removed, label }`,
with a `…older…` sentinel row once `opts.limit` (default 500) states are
reached.

==============================================================================
6. REPEATING                                                   *diffundo-repeat*

With tpope/vim-repeat installed, |.| runs the last :Diffundo command
again with the same arguments.
