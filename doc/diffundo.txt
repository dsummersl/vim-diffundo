==============================================================================
1. COMMAND                                                          *:Diffundo*

:Diffundo earlier [count]                                  *:Diffundo-earlier*
    Open (or update) a vertical diff split showing the buffer as it was
    after |:earlier| [count]. [count] is anything |:earlier| accepts:
    `3`, `10s`, `2f` ... Default `1`. Relative to the state the split
    already shows, so repeating it walks further back.

:Diffundo later [count]                                      *:Diffundo-later*
    The same for |:later|.

:Diffundo search {pattern}                                  *:Diffundo-search*
    Find the undo state whose edit added a line matching {pattern}, show
    it in the diff split, and move the cursor to the match in your buffer
    (or to where the line was, if it is gone). {pattern} is a Vim regex:
    'ignorecase', 'smartcase' and 'magic' apply as for |/|. The search
    register |quote/| is not changed. Repeat to find the next older state.

:Diffundo search! {pattern}
    The same for a line that was removed.

    Search compares each undo state with the state it was edited from
    (its parent in the undo tree, see |undo-branches|), so switching
    branches never counts as an addition or removal.

:Diffundo focus                                              *:Diffundo-focus*
    Open the diff split and focus the history pane: the pane expands into
    the whole undo tree and takes the focus (see |diffundo-api|).

:Diffundo close                                              *:Diffundo-close*
    Close the diff split and its pane.

    Every subcommand opens a floating history pane next to the diff window
    showing the buffer's state and the diff's state, unless the pane is
    disabled with the `history` option (see |diffundo-options|).

==============================================================================
2. SETUP                                                        *diffundo-setup*

`require("diffundo").setup(opts)` is the only way to configure the plugin.
It merges |opts| over the built-in defaults, so every setting is optional
and the plugin works unchanged with no `setup()` call at all. The
defaults, pane keymaps included, are: >lua

    require("diffundo").setup({
      -- show the history pane
      history = true,
      glyphs = { buffer = "@", write = "w", gap = "┆", ellipsis = "…" },
      -- or function(time) -> string
      date_format = "%Y-%m-%d %H:%M:%S",
       -- pane width
      history_width = 40,
       -- expanded-view fold threshold
      fold_min = 3,
      keys = {
        pane = {
          -- next written
          J = function(api) api.move_save(1) end,
          -- previous written
          K = function(api) api.move_save(-1) end,
          -- show under cursor
          ["<cr>"] = function(api) api.place() end,
          -- move buffer there
          ["<c-cr>"] = function(api) api.apply() end,
          -- collapse, return
          q = function(api) api.collapse(true) end,
          -- collapse, return
          ["<esc>"] = function(api) api.collapse(true) end,
        },
      },
    })
<

See |diffundo-options| for the semantics of each option. Pane keymaps
merge per key over these defaults: passing one key replaces only that
binding and leaves the other five intact. A value of `false` (or an
empty string) removes the default binding: >lua

    require("diffundo").setup({
      keys = {
        pane = {
                 -- no longer mapped
          ["<cr>"] = false,
        },
      },
    })
<

==============================================================================
3. OPTIONS                                                    *diffundo-options*

history (boolean, default true)
    When false, the commands open the diff split without the history pane.

glyphs (table, merged over `{ buffer = "@", write = "w", gap = "┆",
ellipsis = "…" }`)
    Glyphs the pane draws: `buffer` marks your buffer's state in the tree,
    `write` a state written to disk (drawn in its own column beside the
    tree), `gap` the gap-row and fold-caption prefix, `ellipsis` the
    truncation marker.

date_format (string, or function(time: integer): string; default
"%Y-%m-%d %H:%M:%S")
    Formats the state timestamps in the pane's border title. A function is
    called with the state's time and must return the title text.

history_width (integer, default 40)
    The pane's width in columns, clamped to the diff window.

fold_min (integer, default 3)
    The expanded pane folds off-trunk branch stretches longer than this
    into `┆  N undos` captions.

==============================================================================
4. API                                                          *diffundo-api*

The pane's keymaps are pane-local; no global keys are mapped and `j`/`k`
stay plain motions. The default bindings are listed in |diffundo-setup|;
each value is a plain Lua function of one argument, the facade `api`, a
table combining the command actions with the pane actions:

  api.earlier(count)       Step the diff back by |:earlier| [count].
  api.later(count)         Step the diff forward by |:later| [count].
  api.undo(seq)            Show undo state {seq} in the diff split.
  api.search(needle, opts) Show the state whose edit added a line
                           matching {needle}; opts.removed = true
                           searches removals.
  api.focus()              Open the diff split and focus the expanded
                           pane.
  api.close()              Close the diff split and its pane.
  api.move_save(dir)       Move the pane cursor to the next (1) or
                           previous (-1) written state.
  api.place()              Put the state under the cursor in the diff
                           split.
  api.apply()              Move the buffer itself to the state under the
                           cursor; the diff stays where it is.
  api.collapse(back)       Collapse the pane; with `true`, return to the
                           source window.

For example, requiring the module to bind a pane key to a facade call
that steps the diff back two undo states: >lua

    local diffundo = require("diffundo")

    diffundo.setup({
      keys = {
        pane = {
          x = function(api) api.earlier("2") end,
        },
      },
    })
<

==============================================================================
5. REPEATING                                                   *diffundo-repeat*

With tpope/vim-repeat installed, |.| runs the last :Diffundo command
again with the same arguments.
